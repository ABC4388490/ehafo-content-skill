# 微信文章手机端排版

## 1. 开头先兑现价值

开头使用 3—5 个短段完成以下任务：

1. 标题优先使用目标用户会直接搜索或询问的问题；只有观点标题比问题本身更具体时才使用观点标题，不用编辑视角替代用户问题；
2. 第一段直接回答标题中的核心问题，或给出最重要结论；
3. 紧接着用一句“不是 A，不等于 B”或同等清晰的边界句，阻断最可能出现的反向误解；没有真实双向误解时不得生造句式；
4. 随后交代 2—4 个最容易出错、最影响行动的要点；
5. 明确读者继续阅读能解决什么。

每段只写一句或一个意思。不得先写行业背景、创作缘由、来源介绍、空泛提醒或“最近有人写错了”。来源与适用范围不晚于相关结论出现，但不抢占第一句话。

采用咨询式表达，而不是政策汇编语气。优先写“先说结论”“真正要准备的是”“你接下来查什么”，少用“全国规则解决的是”“地方文件解决的是”等抽象元话语。同一政策边界在开头讲清后，后文直接进入判断和行动，不换一种措辞重复解释。

## 2. 只保留一条主线

全文只设置一条占主导地位的判断或办理路径。认知误区、材料分类和证据整理只能服务于这条路径，不得各自发展成互相竞争的“三层、四步、五字段”等多套数字框架。

动笔前先建立文章结构卡，不满足时不得进入排版：

1. 只写一个核心问题；标题、摘要、正文和插图均服务于这个问题；
2. 把缺少后就无法完成判断或行动的内容标为“必须信息”，沿主路径优先交付；
3. 把只在异常、特定方式或少数情形下需要的内容标为“补充信息”，放在主路径完成后，不与必须信息并列争夺注意力；
4. 为每个模块只指定一个任务：回答一个判断、给出一个动作、说明一个边界或提供一项必要证据；承担两个以上任务时继续拆分或删除次要内容；
5. 生成后必须进行约 390px 手机预览。普通段落超过 4 个视觉行、单屏连续承担两个以上核心意思，或同屏同时出现多组解释、列表和结论时，返回结构卡重新拆分，不得只靠缩字、加小标题或增加留白掩盖拥挤。

- 需要先纠正认知再办理时，使用“关键判断 → 一个主执行路径 → 下一步”；
- 需要按情形决策时，使用“用户情形 → 对应结论 → 一个主执行路径”；
- 需要按时间办理时，使用“当前状态 → 时间顺序 → 异常处理”。

正文原则上只保留一个编号框架。确有必要增加第二组并列项时，必须证明它解决了不同任务，并使用短段或小标题弱化其视觉竞争；第三组数字框架直接合并或删除。

行动建议必须具体到可执行对象。要求读者查政策时，给出官方入口名称、优先搜索的文件名或关键词，并说明每份文件解决什么问题；不得只写“查询当地通知”。要求读者整理材料时，给出一个统一的证据链或索引方法，不再另起多套分类清单。

初稿完成后，为每个正文段落只标记一种主要作用：新结论、适用边界、判断标准、执行动作或必要证据。同一事实只保留一个主要出现位置；后文没有新增边界、判断或行动，只是换措辞重讲时直接删除。再做一次反向删除测试：删掉某段后不影响用户判断、行动或事实成立，该段即无独立价值，不得保留。

正文插图与文字必须分工。图片已经完整承担步骤、层级、对照或判断路径时，正文只说明如何使用、适用边界或图片未表达的行动，不得逐项复述图内标签。先写满正文再额外插图造成同义叠加时，删除重复正文，而不是保留两份信息。

## 3. 控制手机阅读密度

按约 390px 宽度检查成稿，不以桌面预览代替手机预览：

- 正文左右留白建议为 28—32px；受编辑器限制时选择最接近的安全值；
- 正文字号建议为 15—17px，行高建议为 1.75—1.9；
- 普通段落控制在手机上的 2—4 个视觉行；超过时先删除重复和次要信息，再按意思拆分，复检后仍超过 4 行则不得交付；
- 普通段落之间保留约 24—32px，主要模块之间保留约 48—64px；
- 一屏原则上只承担一个核心意思，不连续堆叠多个解释、列表和结论；
- 第一个可执行判断或动作必须在正文前两屏出现；在它之前不得连续出现超过 3 个解释性文本块；
- 同一核心结论在摘要后的正文中最多完整表达一次，后文只能补充边界、判断或行动，不得换措辞重复；
- 全文只允许一套占主导地位的数字框架；其他并列内容改成短句、小标题或并入主路径，不得同时堆放“三句话、四层、五字段”等命名框架；
- 连续出现 4 个以上纯文本块时，必须先删除重复和次要内容，再把难以用短句说明的关系转成正文插图；不得只靠拆段和增加留白延长文章。

这些数值用于验收阅读感，不得为了机械达标制造空洞留白。

## 4. 建立清晰层级

- 普通正文使用中灰色，主动降低视觉重量；
- 只将决定、动作、风险或关键词改为深灰 `#4A4F4D`、中等字重 `500`；不得使用纯黑或默认粗体，不整段加粗；
- 用居中深灰重点句形成停顿，优先依靠留白和浅色高亮建立层级，字重不超过 `500`；
- 居中重点句可使用底部浅品牌绿色高亮条，不照搬其他品牌的紫色；高亮只覆盖字面下半部约 `50%`，多行时逐行断开，不得铺满整行字高或形成整块色卡；
- 正文确有必要时，可将决定、动作、风险或判断对象中的一个短关键词设为品牌深绿 `#3D8063`、字重 `500`。每处限 3—6 个可见字符，每段最多一处，词组内部禁止换行；不得把整句、整段、标题、摘要、正文小标题或官方依据染绿，也不得与浅绿底重点句叠加；
- 引用规则、特殊提醒或成组情形可使用左侧细品牌绿竖线，内部仍保持灰色正文和局部黑色加粗；
- 列表仅用于步骤、清单、时间点或并列判断，不把普通说明强行拆成列表；
- 正式投递的服务号 HTML 优先用带悬挂缩进的普通段落表示项目符号和序号，不依赖 `ul` / `ol` 的默认样式；必须使用原生列表时，投递前移除列表标签与直接子项 `li` 之间的格式化空白，并以微信草稿箱保存后重开结果验收，避免换行缩进被重写为空列表项；
- 小标题负责转场，不要让所有模块都重复“小标题—正文—列表—图片”的同一结构。

视觉强调必须帮助读者判断重点。页面同时出现多种强调时，减少样式而不是继续叠加。

### 已确认的易哈佛文章视觉基线

用户要求复刻既有易哈佛服务号文章风格或未另行指定视觉风格时，采用以下基线。数值用于约 390px 手机预览和微信富文本验收；微信过滤样式后允许细微字体差异，但不得改变整体层级与阅读节奏。

- 页面：正文纯白，左右各约 30px；不使用外层卡片、阴影、圆角页面壳或灰色正文底。
- 字体：优先 `Noto Sans SC`、苹方或微软雅黑；正文 16px、行高约 1.84、颜色 `#6F7773`。
- 一级正文小标题：21px、行高约 1.45、字重 600、颜色 `#3F4642`；进入新模块前保留约 48—54px 的明显停顿。
- 三级标题或条目标题：17px、行高约 1.65、字重 500、颜色 `#4A4F4D`。
- 普通段落：段后约 22—26px；同一模块内保持连续阅读，不因追求整齐而把每段间距拉到同样大。
- 局部重点：只把决定、动作、风险和关键词设为 `#4A4F4D`、字重 500；不使用纯黑，不整段加粗。
- 结论停顿：可使用居中短句和浅品牌绿底 `#DCEFE7`，一次只强调一个关键判断；色带只覆盖文字下半部约 `50%`，多行时逐行显示，不得使用整行实底。
- 绿色关键词：只在正文必要位置使用品牌深绿 `#3D8063`、字重 `500`；每处 3—6 个可见字符、每段最多一处并保持词组不换行。它是扫描锚点，不是装饰，不得扩展为整句、整段、标题或摘要。
- 风险或边界提醒：使用左侧 3px 品牌绿竖线 `#63A783`，左内边距约 14px；不再叠加底色、图标或标题框。
- 链接：品牌深绿 `#3D8063`，不依靠下划线制造额外噪声。
- 官方依据：14px、颜色 `#7D8581`；只保留用户核对事实所需的正式来源，不在可见文章中展示内部生产字段。
- 图片：顶部图、正文信息图和底部图均按正文有效宽度完整显示；当前锁定的易哈佛文章顶部图因原图内已有留白，其与前后正文的外部间距默认各约 `10px`，不得通过裁剪、缩放或重绘固定图来消除空感；其他正文信息图与后文约 28px，底部图后不人为续接大块留白。发现图片区域过空时，先区分图片内部留白与 HTML 外部间距，只调整可变的外部间距。

内容层级遵循“结论先行—解释误区—给出判断或办理路径—列出准备动作—指出常见走偏方式—收束为一个下一步—提供官方依据”。这是文章的阅读逻辑，不是固定章节数量；按选题删减不必要模块，禁止为了复制样稿而凑出五节。

同一屏原则上只出现一种主要强调方式。绿色仅用于竖线、浅底重点句、正文短关键词、序号或链接等少量位置；正文仍以黑灰白为主。不得新增绿色大标题、整句或整段绿色文字、整块绿色卡片、复杂插画、背景纹理或营销海报式元素。

服务号文章正文、HTML 和微信草稿的用户可见区域禁止出现“选题来源”和“核验日期”。选题来源、检索过程和核验日期继续保存在内部事实卡、验证包或交接记录中，不得因为前台隐藏而停止记录。

## 5. 让图片帮助理解

每篇服务号文章必须包含 1—2 张正文插图。固定顶部图、固定底部图、Logo、二维码和品牌宣传图不计入数量；0 张或超过 2 张均不得交付。插图必须替代或压缩一部分原本难读的文字，不能在保留同义长段落的同时额外叠加图片。

文章插图优先承担以下任务：

- 展示必须携带或识别的真实对象；
- 解释时间、流程或条件之间的关系；
- 展示官方入口或关键操作界面；
- 提供正文无法用短句替代的必要情境。

禁止把正文段落原样做成文字信息卡后再次插入。图片内只保留理解画面所需的最少文字；正文已经完整解释的清单，不在图片中重复一遍。

图片放在相关结论之后或关系解释之前，并与相邻文字共同完成一个信息任务。删除图片不影响理解时，应判断它是否只是装饰；删除图片会损失重要信息时，正文应提供必要的无障碍替代说明。

每张正文图必须有一条无法由相邻短句等价替代的独有信息。没有独有信息的照片、情境图、重复步骤图和纯装饰图不得计数，必须替换成承担解释任务的插图；不得因删除不合格图片而交付 0 张正文插图。

当正文的步骤、对照、时间关系或判断路径被转成信息图后，删除正文中同义的逐项复述；正文只补充图片未表达的来源、适用边界、风险解释和后续行动。文章已有固定顶部品牌图时，Remotion 正文信息图不再放 Logo。

正文信息图使用内容驱动的画布高度，不把 900×600 当成固定模板：

- 默认保持 900px 宽，先按实际内容完成排版，再把画布裁切到能完整容纳内容的最短高度；不得把 480、540 或 600px 当成固定档位；
- 标题、核心关系和行动核对须自上而下形成连续阅读路径，禁止把全部信息挤在上半部、底部留出整块空白；
- 有效内容纵向占比不得低于 72%，顶部空白不得超过画布高度的 15%，最后一个有效内容元素以下的底部空白不得超过画布高度的 8% 且不得超过 48px；
- 内容较少时缩短画布、压缩模块间距或改为横向紧凑结构，不增加装饰、空卡片和重复文案填充；
- 缩放到约 390px 文章宽度后，正文级文字保持约 15px 或更大；若需要缩小到难以阅读才能装下，拆分内容而不是缩字。
- 标题、数字、步骤序号、结论和操作按钮须位于左右各不少于画布宽度 6% 的内容安全区内。

把正文插图写入公众号时，按原始宽高比完整缩放，不得裁切填充：

- 优先使用公众号编辑器“上传图片”插入，不从第三方排版工具或网页直接复制整个图片模块；
- 图片与外层容器不得设置固定像素宽度、`min-width`、负边距、横向位移、`overflow: hidden` 或 `object-fit: cover`；
- 使用微信兼容的等效行内样式实现 `width:100%; max-width:100%; height:auto; display:block; margin-left:auto; margin-right:auto;`；
- 约 390px 正文中不点击放大即可看到图片完整四边、标题和关键信息，并且页面没有横向滚动；点击放大后才完整，直接判定失败。

以上是服务号文章正文插图规则，不适用于服务号独立贴图。不得因文章内嵌图片被裁切，就把独立贴图统一改成某个竖版比例。

渲染后运行 `scripts/check_image_density.py`。脚本只做基础密度门禁，仍须在 390px 手机预览中检查是否显空、是否拥挤、模块关系是否自然。

## 6. 预览与验收

生成 HTML 或发布稿时：

1. 使用微信兼容的行内样式，不依赖外部样式表；
2. 本地预览使用真实相对路径或内嵌图片，正式草稿使用微信返回的图片地址；
3. 不允许保留 `{{IMAGE_URL}}` 等占位符作为可交付预览；
4. 在约 390px 视口检查首屏、最长段落、列表、图片和模块转场；
5. 列表验收必须同时检查项目符号与首行文字对齐、换行后的悬挂缩进，以及是否出现没有文字的空项目符号；任一异常均不得交付。
6. 检查普通内容是否变轻、关键结论是否能被扫到、页面是否存在明显拥挤；
7. 固定顶部图在本地预览中放在标题和摘要之后、正文首段之前，并检查其与上下内容是否自然衔接；
8. 检查正文信息图缩放到实际显示宽度后是否仍可读，必要时使用通栏显示，但不得裁剪图片；
9. 不点击放大，检查正文插图四边、标题和关键信息是否完整可见，并检查页面是否存在横向滚动；
10. 检查图片与外层容器是否存在固定像素宽度、负边距、横向位移、溢出隐藏或裁切填充；
11. 检查信息图是否通过基础密度门禁，底部空白不得超过画布高度的 8% 且不得超过 48px；
12. 检查图片是否加载、文字是否溢出、链接是否可用。
13. 检查正文是否恰有 1—2 张解释性插图，固定品牌资产未被计数，且图片替代了相邻的同义长文而不是增加信息总量。

任一项失败时直接修订并重新预览，不把未修复问题交给用户。

## 7. 微信模板失效时的降级发布

微信编辑器规则变化、复杂样式复制失败或现有模板在草稿箱中显示异常时，先保证内容正确、品牌资产不变和用户能够正常阅读，再恢复视觉细节。更新 Skill 不是备用发布方式；只有经过微信实测的解决方案才能写回规则。

按以下顺序降级：

1. 保留已核验的标题、摘要、正文、事实卡和信息来源，不因排版故障改写事实结论；
2. 原样使用锁定的顶部图、底部图和原始 Logo，不重绘、不裁切、不改字、不重新压缩；
3. 删除外部样式表、复杂嵌套、浮动、定位、变换、阴影、外层卡片和依赖第三方编辑器的布局；
4. 使用微信原生段落、小标题、基础强调、分隔和“上传图片”重新组成文章；必要时牺牲装饰效果，不牺牲信息完整性和手机可读性；
5. 正文插图保持原始宽高比并接近正文有效满宽，不点击放大即可看清；无法稳定显示的信息图先改回正文或拆成更短的插图；
6. 在微信草稿箱保存后重新打开，并发送手机预览，检查文字层级、图片尺寸、完整性、链接和上下间距；
7. 记录失效样式、有效替代方式和实测环境。只有同一方案在至少一篇完整文章中实测通过，才更新对应模板；涉及核心导入方式时，继续用第二篇不同结构文章验证稳定性。

始终分离四类对象：

- 锁定资产：原始 Logo、固定顶部图、固定底部图，只能原样复用；
