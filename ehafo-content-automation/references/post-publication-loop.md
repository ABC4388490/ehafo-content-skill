# 发布后反馈闭环

只在用户要求复盘已发布内容，或当前任务能够读取真实发布数据时使用。目标是让发布结果改变下一轮生产，而不是生成冗长报告。

## 1. 先确定内容任务

不得使用单一指标评价所有内容。先识别本次内容的主要任务：

| 内容任务 | 优先观察 |
|---|---|
| 临近节点提醒、考讯 | 对目标人群的及时触达、关键行动是否发生、明显错误或遗漏 |
| 报考条件、流程、机考说明等长期内容 | 搜索进入、持续阅读、收藏、用户后续问题 |
| 贴图 | 单张是否被完整理解、整套阅读、收藏或分享等深度行为 |
| 品牌内容 | 重复接触、持续关注和后续内容阅读，不用一次点击证明信任 |
| 产品承接内容 | 入口点击只是中间信号；继续观察进入后是否找到匹配功能并完成当前任务 |

平台没有某项数据时明确记为不可得，不使用相邻指标伪装。

## 2. 使用合适的观察窗口

- 即时窗口：发布后约 1 天，检查基础触达、明显错误和异常；
- 中期窗口：发布后约 7 天，检查收藏、分享、留言、继续阅读等深度行为；
- 长期窗口：发布后约 30 天或覆盖实际考试节点，检查搜索、持续访问和产品承接。

按内容生命周期调整窗口。强时效考讯重点看即时和节点窗口；长期搜索内容不得只用首日表现下结论。品牌信任属于长期积累，禁止用单篇内容直接证明。

## 3. 生成极简复盘卡

只记录：

1. 选题、形式、目标用户任务、发布时间；
2. 本次可以获得的真实指标及观察窗口；
3. 最可能的一至两项原因，并分别标注“数据支持”或“待验证假设”；
4. 一条可复用结论；
5. 一个需要更新的位置：选题库、事实卡/知识库、形式规则、文案模板、图片规则、品牌规范或发布门禁。

不得把相关性写成因果。没有对照、重复样本或用户证据时，使用“可能”“待验证”，不要断言标题、排版或 CTA 导致结果。

## 4. 把反馈写回正确位置

- 用户高频问题、搜索词和未解决任务 → 选题库与用户任务卡；
- 年份、地区、政策、时间错误或来源冲突 → 事实卡、知识库与来源门禁；
- 文章和贴图反复出现的结构、密度、留白或可读性问题 → 对应形式模板或图片规则；
- CTA 与用户阶段不匹配、入口后找不到功能 → 品牌承接规则或产品问题记录；
- 多篇同类内容在完整窗口内呈现稳定规律 → 形式判断、标题结构或生产规则。

只修复产生问题的源头。不得只修改已发布成品而让知识库、模板或门禁继续产生同类问题。

## 5. 控制复盘成本

- 重点内容单独复盘；
- 普通内容按周批量复盘；
- 高度模板化内容只记录异常；
- 每轮只更新一个最有证据的系统位置，避免一次数据引发多处规则震荡。

规则更新后，为下一篇同类内容声明验证条件。只有跨样本、跨时间仍成立，才保留为稳定规则。
