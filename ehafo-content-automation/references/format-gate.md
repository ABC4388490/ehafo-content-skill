## 1. 决策顺序

先判断选题价值和事实是否成立，再选择形式。不要先决定做三种内容，再反向拆分素材。

依次判断：

1. 用户此刻最需要知道的是“新发生了什么”，还是“我该怎么判断和处理”；
2. 信息是否存在明确的官方事件、发布时间或行动窗口；
3. 结论是否需要按人群、阶段、地区或条件分类解释；
4. 是否存在适合快速扫读的清单、步骤、对照、时间线或易错点；
5. 每种候选形式是否提供其他形式没有提供的独立价值。

若用户要求 QA、问答、每日一题、一题一解或病例问答，先区分“用户问题解答型”和“题目解析型”，再判断是否适合 QA 结构，并从文章、单张贴图或多张贴图中选择发布载体。QA 不作为第四种形式写入 `selected`。

## 2. 考讯门槛

仅在以下条件全部满足时选择考讯：

- 存在新发布、新开启、新调整、临近截止或结果公布等当前事件；
- 事件有官方一手来源；
- 有明确受影响人群；
- 当前仍有行动价值；
- 能回答“发生了什么、影响谁、何时做、在哪里做、现在做什么”。

普通政策解释、长期备考方法、查分后的常识性建议，不因标题带年份就成为考讯。

## 3. 文章门槛

满足任一条件时优先选择文章：

- 需要按不同人群、阶段或条件分别作答；
- 需要解释规则边界、原因、例外或风险；
- 需要给出无法用一个短结论讲清的判断或办理路径；
- 内容具有长期搜索价值；
- 压缩成图片会遗漏重要限定条件。

文章模块数量由核心任务决定，1 个有效模块也可以成立。若一个短结论已经足以完成用户任务，可使用短文章、简短考讯或单张信息图；不得为了达到模块数量扩写。

## 4. 贴图门槛

仅在信息适合“快速判断、收藏、转发”时选择贴图。合适的内容结构包括：

- 时间线；
- 对照表；
- 分步骤操作；
- 材料清单；
- 自查清单；
- 高频错误与正确做法；
- 多种明确情形的判断路径。

禁止把文章段落逐段搬到图片中。

贴图数量按完成用户任务所需的独立信息模块决定。一个模块能说清就只做一张；多个模块确有不同任务时再拆分。不得为了满足固定张数增加空封面、重复结论或低价值条目。

多张贴图的每一张必须同时满足：

- 解决一个独立问题；
- 用用户会提出的具体问题组织内容；
- 包含明确答案、有用细节和下一步动作，不只有标题、口号或法规摘录；
- 删除后会损失重要判断或操作信息；
- 不与其他图片重复同一结论；
- 手机端可读，不靠大面积留白凑版面。

多张贴图的第 1 张还必须同时满足：

- 承担点击封面作用，但不单独占用一张做空封面；
- 从用户最关心的结果、风险、遗漏或立即行动切入；
- 标题具体说明“为什么现在值得点开”，不用“材料关系”“内容总览”“知识整理”等内部栏目式标题；
- 副标题或正文明确告知后续能解决的核心问题；
- 至少给出一个可立即使用的结论或行动，不能只有悬念。

首图形成的每项核心承诺必须登记，并明确由哪一张后续贴图兑现。不得在首图写“资格证、注册一次理清”，后续却只解释成绩材料。

整组贴图还必须满足：

- 结构采用真实用户路径：按时间顺序、判断路径、对照关系或自查顺序组织；
- 不按政策文件章节顺序机械拆分；
- 用户已经完成的前置条件，除非影响当前办理，否则不单独占用一张；
- 有地区差异时，先给通用结论，再写具体官方入口名称和核对事项；
- “自行查询”“自己去问”“以当地为准”不能单独构成操作建议。

吸引点击不得依赖夸张、恐吓、虚假稀缺或隐瞒关键信息。

## 5. QA 内容结构

仅在以下条件成立时使用 QA 结构：

- 能用一个具体问题触发用户求解、判断或作答；
- 存在可核验的明确答案、解析依据和适用边界；
- 用户看完可形成一个可验证的判断方法；
- 能在短内容内完整交付，不需要另找攻略。

用户问题解答型的简单结论可用短文章或单张贴图；需要按人群、地区、阶段或条件分类解释时优先使用文章，存在可快速扫读的步骤、清单或判断路径时可使用多张贴图。题目解析型的单题和简短解析可用文章或单张贴图；需要展示选项、逐项解析、易错条件或同类知识时，优先使用文章或多张贴图。具体制作规则读取 [qa-content-patterns.md](qa-content-patterns.md)。

## 6. 组合规则

仅在各形式任务不同且互补时组合：

- 考讯＋贴图：官方事件需要快速传播，同时存在时间线或行动清单；
- 考讯＋文章：重大新规需要先报事实，再解释不同人群如何处理；
- 文章＋贴图：复杂问题需要完整解释，同时存在可收藏的自查或步骤；
- 三种全部：重大当前事件、复杂解释和可视化清单三项价值同时成立。

若三种内容只是长短不同或重复同一组结论，只保留最适合的一种。

即使用户说“全部生成”或“一套”，也先执行门禁。排除不适合的形式并说明一句原因，不为满足形式数量牺牲内容价值。

## 7. 决策记录

在验证包中记录：

```json
{
  "format_decision": {
    "selected": ["article"],
    "content_pattern": "qa",
    "rejected": {
      "news": "没有新的官方事件或当前行动窗口",
      "cards": "不足3个适合快速扫读的独立信息模块"
    },
    "card_count": 0,
    "reason": "该选题需要按情形解释，文章能完整保留条件和处理步骤"
  }
}
```

允许的形式值为 `news`、`article`、`cards`。`selected` 不得为空，`outputs` 只能包含已选择的形式。

`content_pattern` 可使用 `standard` 或 `qa`。选择 `qa` 时仍须遵守发布载体对应的文章或贴图门槛。
